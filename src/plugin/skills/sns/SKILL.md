# sns: build in public の素材採取と投稿ドラフト

前提となる設計原則:

- **要約が AI 臭の根源**。あとでまとめて書くかぎり要約の匂いは消えない。素材は出来事の直後に生の解像度（固有名詞・数字・困った瞬間）のまま採取し、作文は常に1素材=1投稿。複数素材や一般論を1本に混ぜた瞬間に要約へ戻る。
- **公開は人間が行う**。このスキルの出力はドラフトまで。投稿 API の呼び出しや自動公開はしない。

## material モード（採取。数秒で終える）

1. 素材置き場は `~/dev-notes/sns/materials.md`（無ければ見出しだけのファイルを作る）。
2. 次の形式で1行追記する:
   `- [ ] YYYY-MM-DD <プロジェクト名>: <出来事。固有名詞・数字・困った瞬間をそのまま>（素材: <録画・スクショのパス>）`
   録画・スクショが無ければ `（素材: ...）` は省略。
3. 採取基準: 固有名詞か数字が2つ以上残っている具体的な出来事だけ。カテゴリ語（「知見を得た」「設計を改善した」等）に丸まった時点で素材価値はない。該当が無ければ何も書かず黙って終える。
4. 守秘: 顧客名・社名・未公開の他社事情が特定できる内容は採取しない。一般化できる技術的出来事は可。
5. このモードではドラフト化・文体調整・重複確認をしない。

## draft モード（作文）

1. `materials.md` の未使用（`- [ ]`）素材を新しい順に提示し、1件選ぶ（引数で指定があればそれ）。
2. 選んだ1素材だけから1案つくる。他の素材・一般論・過去の投稿を混ぜない。
3. 構成: フック1行（数字か困った瞬間）→ 空行 → 展開 →（列挙が3点以上あるときだけ箇条書き）。全体で全角140字以内。ハッシュタグ・絵文字は使わない。
4. 文体の禁止ルール:
   - 体言止めを2連続以上使わない
   - 「AはX。でもBはY。」の対句構文を使わない
   - カテゴリ語でなく、画面に出てくる実物の言葉・固有名詞・数字で書く
   - 「なので」で問題→解決へ直結させない。解決側も出来事として書く（どのツールが・いつ・何をするか）
   - 最後の文で教訓をまとめない。言い切らずに終わってよい
   - 禁止語: 「正解だった」「〜が本質」「〜こそが」
5. 提示前のセルフチェック:
   - 特定の一日の出来事として読めるか（誰の体験でもない一般論になっていないか）
   - 課題→解決→教訓の三幕構成で閉じていないか
   - 体験した本人にしか書けない細部が1つ以上あるか
6. 添付素材: 素材行に素材パスがあればそれを添付する前提の構成にする。無ければ「撮るなら何をどの画面で（30秒以内）」を1行添える。
7. ユーザーが採用したら該当行を `- [x] ...（投稿: YYYY-MM-DD）` に更新する。ボツなら未使用のまま残す。
