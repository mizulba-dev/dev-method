# create-qa-data-skill: QAデータ準備skillの生成

既存の安全なデータ機構を薄く包む `prepare-qa-data` を生成する。汎用DB複製、マスキング、合成データ生成、環境provisioningを作らない。生成作業中にデータ変更コマンドを確認目的で勝手に実行しない。

## 1. 対象と必要状態を確定する

対象リポジトリ、想定QAシナリオ、対象環境を確認する。対象環境が未指定なら `local` とする。シナリオごとに必要な状態、利用者・権限差、安定して参照したい識別子を列挙する。

本番環境は常に禁止する。共有環境を許可候補にするのは、ユーザーまたはdirectionが環境を明示し、既存文書が安全な作成・限定cleanupを裏づける場合だけとする。

## 2. 読取中心で既存手段を探索する

リポジトリの指示と環境文書を読み、ファイル検索、コード検索、設定の閲覧だけで次を調べる。

- seed、fixture、factory、mock、テストヘルパー
- 公開済みの内部API・CLI、Testcontainersや同等のローカルコンテナ
- QA・E2E・開発環境の起動方法、認証方法、cleanup手順
- 対応環境と禁止環境、必要な環境変数の**名前**
- 冪等性、run単位の識別方法、prepare後・cleanup後の検証方法

seed、SQL、API、migration、コンテナ起動など状態を変えるコマンドは探索中に実行しない。秘密値や実データを読んだり出力へ転記したりしない。

## 3. 採用手段を決める

シナリオの必要状態を満たす既存手段を、fixture・テストヘルパー、既存seed/API、ローカルコンテナ、環境文書化済み手順の順に検討する。安全性、環境適合、冪等性、限定cleanup、安定識別子を根拠に最小の組み合わせを選ぶ。

実行コマンド、許可環境、cleanup対象のいずれかを根拠から特定できない場合は推測で埋めない。該当項目を `BLOCKED: <不足情報と確認先>` として残す。危険な代替コマンドを創作しない。

## 4. テンプレートから生成案を作る

`assets/prepare-qa-data/SKILL.md` を読み、プレースホルダーを探索結果で置換する。必ず次の契約を残す。

- 対応環境と禁止環境
- 前提条件と必要な環境変数名（値は禁止）
- 環境別のprepare手順と準備完了の検証方法
- シナリオから参照する安定識別子
- 冪等性と再実行時の挙動
- このskillが作成した対象だけを消すcleanupとcleanup後検証
- 共有資源への影響
- 失敗時の停止・復旧方法

スキル本文へ秘密値、顧客データ、環境固有の実認証情報を書かない。

## 5. 両クライアントへ安全に配置する

正本を `.agents/skills/prepare-qa-data/SKILL.md`、Claude Code用同期先を `.claude/skills/prepare-qa-data/SKILL.md` とする。

1. 両方とも存在しなければ、必要な親ディレクトリを作り、同じ生成案を両方へ配置する。
2. どちらか一方でも既存ファイルがあれば上書きしない。既存両配置の差と生成案との差分、採用根拠、残る `BLOCKED` を提示して停止する。
3. ユーザーが更新案を承認した後だけ正本を更新し、同一内容を同期先へ反映する。
4. 生成・更新後にファイル内容の完全一致を確認する。

既存skillが片側だけにある場合も、暗黙コピーせず更新案として扱う。

## 6. 検証して報告する

生成された両ディレクトリに対し、利用可能ならskill-creatorの `quick_validate.py` を実行する。利用できないクライアントでは、YAML frontmatterが `name: prepare-qa-data` と具体的な `description` だけを持ち、ディレクトリ名と一致すること、必須契約の全節が埋まっていることを静的確認する。

最後に次を報告する。

- 採用した既存機構と根拠、実行しなかったデータ変更コマンド
- 対応・禁止環境、必要な環境変数名、安定識別子
- prepare・verify・cleanup・復旧の概要と残る `BLOCKED`
- `.agents` と `.claude` の配置先、内容一致、validation結果
- 既存skillがある場合は未適用の差分と承認待ちであること

生成後もprepareやcleanupをこのcreator自身では実行しない。
